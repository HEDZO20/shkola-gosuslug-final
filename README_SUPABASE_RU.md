# Подключение и защита Supabase

## 1. Настройка базы

1. Создайте проект в Supabase.
2. Откройте **SQL Editor → New query**.
3. Скопируйте туда весь файл `setup.sql` и нажмите **Run**. Файл можно запускать повторно: он обновляет схему и политики без удаления уроков и учеников.
4. Выполните в SQL Editor:

   ```sql
   select * from public.make_user_admin('ВАШ_EMAIL');
   ```

   Эта функция специально недоступна через публичный API и работает только из SQL Editor.
5. В **Project Settings → API** скопируйте Project URL и anon/publishable key в `supabase-config.js`.
6. Не добавляйте в сайт `service_role` или secret key. Для браузера нужен только публичный anon/publishable key.

После обновления этой версии обязательно запустите свежий `setup.sql` ещё раз. Он закрывает возможность самостоятельного одобрения ученика, скрывает ответы теста и переносит подсчёт балла на сервер.

## 2. Чтобы Free-проект не приостанавливался

В проект добавлен workflow `.github/workflows/supabase-keepalive.yml`. Он делает маленький запрос к базе каждые 8 часов.

Дополнительные GitHub Secrets не нужны: workflow считывает публичные Project URL и publishable key из `supabase-config.js`. Откройте **Actions → Supabase keep-alive → Run workflow** и убедитесь, что запуск зелёный. Запланированные GitHub Actions могут запускаться с небольшой задержкой.

Workflow должен находиться в основной ветке. Для keep-alive удобнее приватный репозиторий: в публичном репозитории GitHub автоматически отключает расписания после 60 дней без активности в репозитории. Если репозиторий публичный, периодически проверяйте вкладку Actions либо используйте внешний HTTPS-монитор с тем же GET-запросом.

По официальной документации Supabase, несколько пользовательских запросов к базе в день обычно достаточно, чтобы Free-проект не считался неактивным. Но абсолютную гарантию отсутствия автоматической паузы даёт только платный Pro-план.

## 3. Проверка после подключения

- Зарегистрируйте тестового ученика.
- Убедитесь, что до одобрения уроки закрыты.
- Одобрите ученика в админке.
- Пройдите первый урок и тест.
- Проверьте, что следующий урок открылся, а правильные ответы не видны в запросе `get_lesson_quiz`.
- Проверьте загрузку файла меньше лимита Storage.
